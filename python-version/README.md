# Webhook Relay

Small webhook relay service for the TJM Labs take-home. Callers register destinations and event types, submit events, and inspect delivery outcomes. A background worker delivers signed HTTP POSTs with retries.

**Stack:** Python · Django · django-ninja · SQLite · pytest · uv

## Quick start

```bash
cd tjmlabs-task

# Install dependencies
uv sync --group dev          # preferred
# or: python -m pip install django django-ninja cryptography pytest pytest-django

# Optional: copy env template (not required for local DEBUG)
cp .env.example .env

# Database + API key
python manage.py migrate
python manage.py create_api_key    # save the whr_... key — shown once
```

Run **two processes**:

```bash
# Terminal 1 — API
python manage.py runserver

# Terminal 2 — delivery worker
python manage.py run_delivery_worker
```

## API

All endpoints require `Authorization: Bearer <api_key>`.

| Method | Path | Description |
| --- | --- | --- |
| `POST` | `/api/v1/subscriptions` | Register destination + event types → `201` |
| `GET` | `/api/v1/subscriptions/{id}` | Get subscription (no secrets) |
| `POST` | `/api/v1/events` | Ingest event → `202` (or `200` on idempotent replay) |
| `GET` | `/api/v1/subscriptions/{id}/deliveries` | Inspect delivery status |

### Create subscription

```json
POST /api/v1/subscriptions
{
  "destination_url": "http://127.0.0.1:9001/orders-webhook",
  "event_types": ["order.created", "order.updated"],
  "destination_secret": "optional-receiver-credential"
}
```

Returns `signing_secret` (`whsec_...`) **once**. Subsequent GETs omit it.

### Send event

```json
POST /api/v1/events
{
  "event_type": "order.created",
  "payload": { "order_id": "ord_123", "total": 42.5 },
  "idempotency_key": "optional-client-key"
}
```

Fan-out is transactional: event + delivery rows are persisted together, then the worker delivers asynchronously.

### Outbound webhook (worker → destination)

| Header | Value |
| --- | --- |
| `X-Webhook-Id` | delivery id |
| `X-Webhook-Timestamp` | Unix seconds |
| `X-Webhook-Signature` | `v1=<hmac_sha256_hex>` |
| `X-Webhook-Event-Type` | event type |
| `X-Webhook-Event-Id` | event id |
| `Authorization` | `Bearer <destination_secret>` if provided at subscribe time |

Canonical HMAC input: `{timestamp}.{raw_body_bytes}`. Receivers should reject timestamps outside ±5 minutes.

### Delivery policy

| Setting | Value |
| --- | --- |
| Max attempts | 4 (1 initial + 3 retries) |
| Backoff | 1s → 5s → 25s |
| HTTP timeout | 5s |
| Retryable | timeout, network error, 408, 429, 5xx |
| Terminal | 2xx → `succeeded`; most 4xx / exhausted → `dead` |

## Configuration

| Variable | Required | Default (local) |
| --- | --- | --- |
| `DJANGO_SECRET_KEY` | prod | dev fallback |
| `DEBUG` | no | `true` |
| `ALLOW_INSECURE_WEBHOOKS` | no | `true` in DEBUG (allows `http://127.0.0.1`) |
| `WEBHOOK_RELAY_FERNET_KEY` | prod | auto from `.dev-fernet-key` in DEBUG |

In local DEBUG mode, encrypt/decrypt always reads `.dev-fernet-key` so the API and worker stay in sync.

**Production:** set an explicit Fernet key:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

## Troubleshooting

**`Failed to decrypt stored secret`** — subscriptions were encrypted with a different key (common after key/config changes):

```bash
python manage.py reset_webhook_data --yes
# Restart API + worker, then recreate subscriptions in Postman
```

**Deliveries stuck `pending`** — ensure the worker is running in a second terminal.

**401 Unauthorized** — set Postman `api_key` or pass `Authorization: Bearer whr_...`.

## Key decisions

- **DB outbox + management command worker** instead of Celery/Redis — lean deps, durable fan-out, retries, and inspectability on SQLite without extra infra.
- **Async delivery only** — ingest returns after commit; outbound HTTP never blocks the API path.
- **HMAC-SHA256 + timestamp** — industry-familiar authenticity for receivers; no mTLS needed for MVP.
- **Fernet encryption at rest** for signing secrets and optional destination credentials; dev key in `.dev-fernet-key` shared across processes.
- **Hashed API keys** — bootstrap via management command; no public signup.
- **At-least-once delivery** — receivers dedupe on `X-Webhook-Id` / event id.
- **Optimistic job claiming** — `lock_token` + lease reclaim; portable to Postgres `SKIP LOCKED` later.

## What I'd harden before production

- Postgres with `SELECT FOR UPDATE SKIP LOCKED` for multi-worker claiming
- Full SSRF controls (private IP deny, DNS rebinding, no redirects)
- Rate limiting per API key and per destination
- KMS-backed secret rotation and key versioning
- Metrics/tracing (Prometheus, structured log shipping)
- HTTPS-only destinations, circuit breakers, auto-disable failing subscriptions
- Delivery replay API, pagination, health/readiness endpoints

## Deliberately left out (core slice)

- Rotate signing secret, PATCH/soft-delete subscriptions
- Separate Account model / multi-tenant admin UI
- Delivery detail-by-id endpoint, cursor pagination
- Health endpoints, metrics hooks
- Celery / Redis / Kafka
- Aggressive SSRF (basic URL validation only; localhost HTTP allowed in DEBUG)
